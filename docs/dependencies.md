# Dependencies between the subsystems

This doc is generated by `uv run tools/dependenciesdoc.py --write` from the files of data/ and is checked in CI. Do not edit it by hand.

It classifies the state that the 12 simulation subsystems share, so that a reader who has not read the source can see which subsystems can be cut apart and which must stay together. The classes come from 84 scenarios of reference/scenarios (tools/depclass.py, tools/phaseclass.py, tools/presreads.py; step 1 is tools/accesslog.py).

## Classes

An edge is a writer, a reader, an item and a phase. The class is the first that applies:

- **ordered**: the order of draws from a random stream, sounds or UI records is the state, whichever subsystem comes first. The streams are items (`rng.parkMiller` for RandomInt, `rng.crtHoldrand` and `rng.crtLoad` for GameRand), so two subsystems that draw from one stream in a phase already have an `ordered` row; the draws tables below add the counts per entity, not new edges.
- **immediate**: some run shows a read of the item after the writer wrote it in the same phase. The writer must run first.
- **deferrable**: the reader read before the writer wrote, and nobody read the writer's value before the phase ended. The write could be queued to the end of the phase.
- **read-only**: the reader reads the item and no run shows anyone writing it in that phase.
- **unobserved**: an edge of data/coupling.csv that no run enters.

Edges in data/dependencies.csv: 66 ordered, 379 immediate, 31 deferrable, 1132 read-only, 1272 unobserved.

## Cutting rule

S can be cut from T when no edge between them, in either direction, is `immediate` or `ordered` within a phase in data/dependencies.csv. Edges that cross a phase boundary (data/phase_dependencies.csv), and `deferrable`, `read-only` and `unobserved` edges, can be served by a phase-end snapshot or event.

## Tightly coupled groups

These are the largest sets of simulation subsystems joined by `immediate` or `ordered` edges. Each must stay one ordered pass per phase. They are the connected components, of two or more members, of the undirected graph of those edges, per phase and over all phases. The random streams need no rule of their own: two subsystems that draw from one stream in a phase have an `ordered` row on it, so the streams are already in the groups. Under each phase, `streams` lists the subsystems that the `rng.*` rows join.

**Phase `explosions`**:

- 2 members: weapons, map

**Phase `features`**:

- 5 members: features, ai, weapons, units, map

**Phase `players`**:

- 10 members: economy, ai, pathfinding, weapons, targeting, los_radar, orders, units, players, map
- streams: 2 `ordered` rows on `rng.*` join ai, targeting

**Phase `projectiles`**:

- 8 members: features, ai, weapons, targeting, los_radar, orders, units, map
- streams: 6 `ordered` rows on `rng.*` join features, ai, weapons

**Phase `tail`**:

- 2 members: los_radar, players

**Phase `units`**:

- 10 members: economy, features, ai, weapons, targeting, los_radar, orders, units, players, map

**All phases together**:

- 11 members: economy, features, ai, pathfinding, weapons, targeting, los_radar, orders, units, players, map
- streams: 32 `ordered` rows on `rng.*` join features, ai, weapons, targeting, orders, units, map

## Limits and known gaps

Step 1 (the access log, tools/accesslog.py) sees less than the whole program, and every class inherits that:

- Only native modules are instrumented. The WASM modules are not, so a run in WASM mode records nothing.
- One thread is recorded. Accesses of other threads are not seen.
- The CRT's string and sort functions are not instrumented, so what they read or write is not attributed.
- The rest of the list in the docstring of tools/accesslog.py applies as written there.
- Coverage: an edge is classified from the scenarios of the suite and no more. `deferrable`, `read-only` and
  `unobserved` claim only that those runs did not show a read after a write. A scenario that reaches the code
  differently could.

Gaps in what the data say:

- There are no `net` rows. No scenario of the test mode runs marker 0 of a tick, so the `net` phase and the
  boundary `0|1` have no edges.
- Some rows of data/state_classes.csv have no map symbol, so they never appear as items. A coupling edge on one of
  them is `unobserved` whatever the code does.
- Accesses to `unresolved:*` items (an image or block range that no state row names) are dropped and are not edges.
- The replay corpus (#389) is not played by accesslog.py, so the classes come from the scenario suite alone (#847).
- The `ui-action` rows of data/presentation_reads.csv are an upper bound: they come from the static reach of the input
  handlers, because scripted UI input is not logged.
- Static-only items of ambiguous or unseen types have no row.
- Events after marker 7 are not attributed to a phase of their own.
